# Sistema de evaluación

La Academy combina validación local y revisión humana.

## 1. Tests obligatorios

Cada semana tendrá tests que comprueban requisitos objetivos de la tarea.

Ejemplos:

- Existencia de archivos requeridos.
- Estructura HTML mínima.
- Elementos y atributos obligatorios.
- Funciones JavaScript esperadas.
- Comportamientos del DOM.
- Persistencia con LocalStorage cuando corresponda.
- Tests unitarios e integración en niveles posteriores.

Si un test obligatorio falla, la tarea todavía no está técnicamente completa.

## 2. Challenges opcionales

Los challenges sirven para que alumnos más avanzados continúen mejorando sin bloquear al resto del grupo.

Los challenges no deben hacer fallar la validación obligatoria de la semana.

## 3. Code Review

Pasar todos los tests no significa aprobar automáticamente la tarea.

El instructor también revisará:

- Legibilidad.
- Organización del código.
- Nombres de variables, funciones y archivos.
- Buenas prácticas.
- Uso correcto de Git.
- Capacidad del alumno para explicar su solución.

## 4. Flujo de aprobación

```text
Tarea
  ↓
Tests locales
  ↓
Correcciones
  ↓
Repo personal actualizado
  ↓
Enlace al instructor
  ↓
Code Review
  ↓
Aprobado
```

Los tests no se ejecutan automáticamente en GitHub en este programa.

## 5. Evolución de los tests

### Nivel inicial

Validaciones estructurales de HTML y CSS.

### JavaScript

Tests de funciones, valores, arrays, objetos y lógica.

### DOM

Tests sobre elementos, eventos e interacción.

### Front-end moderno

Vitest / Testing Library para componentes y comportamiento.

### Full Stack

Tests de APIs, servicios, integración y bases de datos.

El objetivo no es solo comprobar que "funciona", sino introducir al alumno gradualmente en una cultura profesional de testing, debugging y revisión de código.
